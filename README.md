# HermesEnabler — watchOS 26.x Compatibility Research

**Native Hermès watch face investigation · First-generation Apple Watch Ultra**

**Status: BLOCKED — the current approach has not enabled native Hermès watch faces.**

[English](README.md) · [简体中文](README.zh-CN.md) · [Development history](#development-history) · [Original HermesEnabler](https://github.com/pookjw/HermesEnabler) · [Upstream Issue #17](https://github.com/pookjw/HermesEnabler/issues/17)

## About this project

I built upon [pookjw/HermesEnabler](https://github.com/pookjw/HermesEnabler) to investigate whether **native Hermès watch faces** could be enabled on my **first-generation Apple Watch Ultra**, running **watchOS 26.6.1 (build 23U95)**. This public repository preserves on-device observations, matching-firmware analysis, related source code, unsuccessful attempts, and corrected findings. Parts of the code and documentation were AI-assisted.

**This is not a verified working unlock utility, and no IPA has been demonstrated to unlock native Hermès faces on this device and firmware.** The research is paused, not deleted or declared impossible for all future discoveries.

| Scope | Details |
|---|---|
| **Test device** | Apple Watch Ultra (first generation), `Watch6,18` / `n199ap` |
| **Target firmware** | watchOS **26.6.1**, build **`23U95`** |
| **Goal** | Native system recognition, addition, and persistent display of genuine Hermès faces |
| **Status** | **BLOCKED — not unlocked** |
| **Areas investigated** | MobileGestalt, ClockKit, NanoTimeKit, native face eligibility and system permissions |

## Verified findings

| Observation | Result |
|---|---|
| Protected MobileGestalt cache read | **Succeeded**. `DeviceBrand=0`; the corrected descriptor is **index 103 / value offset 0x338 / validity offset 0x164F**. An earlier index 206/0x670 interpretation was wrong |
| Protected system cache write | **Failed**. The actual watch returned **`EPERM`** at `open(O_RDWR)`, even after a Class-13 sandbox extension was consumed |
| Hermès 2025 eligibility | Matching-firmware static checks exclude the observed `deviceCategory=4` |
| Hermès Circulaire / Poodle eligibility | The authentic face archive references `com.apple.NTKPoodleFaceBundle`; its matching-firmware restriction function returns **restricted** for measured device attributes |
| FaceBundleManager exception | Resolved to ClockKit `_CLKIsFaceSnapshotService`, **not** a general native-face unlock authorization |
| Native Hermès face activation | **Not achieved**. No verified persistent native face display |

These results combine real read-only watch logs and static analysis of the matching **23U95** firmware. Success with a different watch model or watchOS 27 tool does not establish permission to modify this device.

## Why work is paused

The tested methods cannot write the watch's protected MobileGestalt cache. Separately, obtaining write access would **not automatically satisfy** the system's face eligibility and add-to-library checks.

I will only reconsider this route with reproducible evidence **on Watch6,18 / 23U95**: a valid system-authorized write or equivalent capability, safe write/readback and reboot persistence, and an actual native Hermès face being added and displayed. None of these three milestones has been met.

## Upstream HermesEnabler v1.5 review (November 12, 2026)

I reviewed the [official v1.5 release](https://github.com/pookjw/HermesEnabler/releases/tag/1.5), published **09:38 Beijing Time on November 12, 2026**. It adds watchOS **27.2 beta 1 (`24S5112a`)**, Ultra face layout choices, Watch/iPhone backup transfer, backup management, and post-write verification with rollback attempts.

**This does not resolve the Watch6,18 / 23U95 permission failure.** The latest upstream `BQCore.m` still attempts `open(O_RDWR | O_CLOEXEC | O_NOFOLLOW)` on the protected cache, and verification runs only after that write path succeeds. [PR #51](https://github.com/pookjw/HermesEnabler/pull/51) expressly says the MobileGestalt modification mechanism is unchanged. The upstream supported-build table excludes `23U95`; [PR #52](https://github.com/pookjw/HermesEnabler/pull/52) reports a Hermès success on **Series 10 / Watch7,9**, not Ultra 1.

I have documented the comparison **without merging v1.5 or installing an IPA**. Native Hermès remains **BLOCKED** on the target device. See [source-level comparison](research/Upstream-HermesEnabler-v1.5-Compatibility.md).

## Original HermesEnabler 1.5: Xcode simulator investigation (November 12, 2026)

I ran the **original author's HermesEnabler 1.5** on the **Apple Watch Ultra 3 / watchOS 27.0 Simulator** in Xcode. The app displayed a MobileGestalt access alert, while the console recorded `escape: all strategies failed (last=-5)` targeting the protected `systemgroup.com.apple.mobilegestaltcache`. This is a **simulator observation**, not evidence that upstream 1.5 fails on supported physical watches.

Earlier, simulator-preview changes were mistakenly committed to this Ultra 1 research fork's `ContentModel.swift` and `ContentView.swift`; both original files were subsequently restored ([`0cb47be`](https://github.com/ZhuoXuan-MY/HermesEnabler--WatchOS26.X/commit/0cb47be30332ae8d4c9e15ae4dbd6bfa121e9f88), [`314ff4d`](https://github.com/ZhuoXuan-MY/HermesEnabler--WatchOS26.X/commit/314ff4d8c57398bea77d254ac2da4ef623b29cf4)). After confirming the correct source repository, I published a **separate, upstream-1.5-specific simulator UI preview patch**: [git patch](patches/HermesEnabler-1.5-watchOS-Simulator-UI-Preview.patch), [complete replacement `ContentView.swift`](patches/upstream-1.5/ContentView.swift), and [detailed development/test history](research/Upstream-HermesEnabler-v1.5-Simulator-Preview.md).

**Validation:** The patch matches the original upstream 1.5 file, but **has not been built or run in Xcode**. Simulator screens are read-only previews with disabled controls; the original physical-watch code is preserved. This is **not a native Hermès unlock or a merger of upstream v1.5 into the watchOS 26 fork**.
