## Why V27 needed a second pass

V24/V25 completed the ordinary `NTKPoodleFace.isRestrictedForDevice:` branch. For measured `deviceCategory=4`, `collectionType=9`, `NTKShowHardwareSpecificFaces=false`, that method returns restricted. Repeating the same watch-side getters will not solve the remaining question.

V17/V18 located an **additional call** from `NTKFaceBundleManager` after the normal face check rejects:

| Role | Verified 23U95 unslid VA | Evidence |
|---|---|---|
| Restricted-face lookup exception stub | `0x55CE73DC` | Called from `0x544B0F9C` (bundle-ID lookup) and `0x544B1174` (legacy style lookup) |
| Independent internal-build-related stub | `0x55CE731C` | Called by `NTKInternalBuild` / `NTKShowHardwareSpecificFaces` |
| Bundle-ID lookup call-site window | `0x544B0F94` | `isRestrictedForDevice:` then exception branch |
| Legacy style lookup call-site window | `0x544B1164` | Same restricted-result handling in a different method |

Addresses `0x55CE73DC` and `0x55CE731C` are **not interchangeable**. The fact they are 0xC0 apart does not prove common function identity.

A previous `ipsw dyld a2s` lookup returned `__TEXT_STUBS ?`. That is an unresolved result, not an Apple-private function name. The standalone NanoTimeKit binary did not provide a conclusive bind mapping.

## New script and verification

`scripts/ro23-v27-1-stub-binding-audit.sh` uses the owner's **already extracted** full shared cache. It:

1. Rejects missing files, mismatched architecture filenames and cache paths not identifying `23U95` / `Watch6,18`.
2. Runs `ipsw dyld a2s --image --mapping`, `a2f`, `a2o --image-rel`, and **16 bounded instructions** via `disass` on each of the two *separate* stub addresses.
3. Disassembles both NanoTimeKit call-site windows independently to preserve branch context.
4. With optional `--extended`, inspects `ipsw dyld macho ... NanoTimeKit --stubs` and `ipsw dyld imports ... --image NanoTimeKit` for **candidate** stub/bind information. Candidate imported symbols are *not* automatically assigned to a particular address.
5. Preserves command failures through Bash `pipefail` and limits displayed output without suppressing the underlying exit code.

**Tests run during preparation:** Bash syntax check; an isolated mock `ipsw` harness verified the expected 12 commands in extended mode and nonzero exit status when both `a2o` calls failed. These checks verify **script control flow only**. The exact 23U95 dyld shared cache was **not** available in the analysis environment; no authentic stub identity has been recovered in this revision.

### Run on the existing Mac repository (does not install to the watch)

```bash
git -C "$REPO" fetch origin research/ro23-v27-1-stub-binding-audit
git -C "$REPO" show FETCH_HEAD:scripts/ro23-v27-1-stub-binding-audit.sh | bash -s -- --extended
```

The default shared-cache path is the existing `$HOME/Downloads/RO23-23U95-Static/DSC/23U95__Watch6,18/System/Library/Caches/com.apple.dyld/dyld_shared_cache_arm64_32`. The script takes an optional positional cache path **only when it identifies the same firmware**. It does not re-download an OTA or touch the paired watch or iPhone. The optional extended inventory could be slower on the multi-GB cache.

### How to interpret the output

- **Named resolution with concrete address linkage:** inspect the full stub disassembly, symbol/bind record and caller control flow before labeling the exception predicate. Document its exact address and source, not just a matching word in a list.
- **`__TEXT_STUBS ?` or an anonymous branch:** unresolved. The branch target and binding/fixup metadata still need static analysis; a nearby imported symbol or relative offset is insufficient.
- **Failure or wrong cache:** no conclusion about the watch's authorization state. Do not reinterpret a lookup-tool error as a permissions bypass.
- **Name identified:** still *not* a successful add-to-library operation. `_NTKCanAddWatchFace`, the face descriptor availability check, the physical device's bundle eligibility and the system face persistence path are separate gates.
