## V19.3 — Actual ClockKit preference content (owner screenshot, 2026-11-11)

The owner opened \`Watch [com.apple.Bridge] / Library / Preferences / com.apple.ClockKit.plist\` (80 bytes) **without editing** it. Filza displayed a \`Dictionary[1]\` with one String entry:

\`\`\`text
HandFactoryCachedBuild = "24B5089g"
\`\`\`

The build string **24B5089g** matches **iOS 27.2 beta 2**, released September 21, 2026 according to independently maintained build catalogs. It is **not** the Ultra 1's validated watchOS build \`23U95\`. Because the key is explicitly a *cached-build* marker, it may be stale after upgrades; the screenshot does **not** prove the iPhone's current OS build.

Neither the screenshot nor the observed key establishes a Hermès authorization entitlement, \`CLKDevice.deviceCategory\` override, \`DeviceBrand\` mutation, or FaceBundle registration bypass. The semantic meaning of \`HandFactoryCachedBuild\` has **not been reverse engineered**, so treating it as a clock-hand rendering cache is a name-based hypothesis, **not proven implementation**.

**Decision:** Do not modify this file or its build marker. Mark it low priority. Next, check only the **top-level directory names** (or any access error) of the previously listed iPhone component \`com.apple.NanoTimeKit.CreateWatchFace\`, without reading pairing secrets or changing any files.

## V19.4 — CreateWatchFace preferences (owner screenshots, 2026-11-11)

Owner screenshots demonstrate Filza can list `Library/Preferences` under the iPhone-side `com.apple.NanoTimeKit.CreateWatchFace` component. Exactly two plist files are shown:

- `com.apple.NanoTimeKit.face.plist` — **111 bytes**.
- `com.apple.ClockKit.plist` — **77 bytes**.

Two subsequent plist-editor screenshots show the following **actual values**:

```text
Dictionary[2]:
  HandFactoryCachedBuild = "20F66"
  UltraFaceWasAddedToLibrary = YES

Dictionary[1]:
  HandFactoryCachedBuild = "21C66"
```

**Source distinction:** The screenshot of the plist edit view does not display the file name; assigning the two-key dictionary to the larger `com.apple.NanoTimeKit.face.plist` and the one-key dictionary to the smaller `com.apple.ClockKit.plist` is a **size-based inference**, not absolute proof of file-to-key attribution.

**Interpretation:** `UltraFaceWasAddedToLibrary` plausibly records that an Ultra-specific face was added to the face library, but public searchable references did not establish the key's implementation. It is **not** evidence that a Hermès face was installed, the brand or category was altered, or the on-watch eligibility checks were bypassed. `HandFactoryCachedBuild` also appears in another Bridge container with value `24B5089g`, illustrating that each local preference store can contain distinct cached build strings and these should **not be conflated with the watch's actual `23U95` OS build**.

**Decision:** Stop this preference-file search. Do not edit `UltraFaceWasAddedToLibrary`, change cached build strings, click Delete or Save, or export pairing secrets. The project remains a research-only native watchface investigation; no verified unlock or protected watchOS writes.
