# RO23 V19.1 — Filza v27.2.2 exact-source audit and iPhone Watch App container

Date: 2026-11-11. Target: paired iPhone + Apple Watch Ultra 1 (Watch6,18), watchOS 26.6.1 / 23U95.

**Result:** Filza on the iPhone can list the `com.apple.Bridge` application data container. This does **not** prove iPhone SystemGroup access, watchOS system write access, or unlocking an authentic Hermès face.

## Source verification

The user provided `filza27.2-v27.2.2.zip` directly. Audited it offline as an archive, without executing any code.

- Archive size **3,271,746 bytes**, 302 entries, ~5.01 MiB extracted.
- SHA-256: `2711ade73f7a383862b6fa0c451fddb69595f970441196cac2d58ebc6c7f7b41`
- Package root: `filza27.2/`
- The exact Gitea release page was not fetched, so the uploaded archive's contents cannot establish that the installed `.ipa` was built from exactly this commit, nor prove signing provenance or actual write authorization.
- Historical V19 note saying exact source was unavailable is corrected.

## Runtime evidence provided by the owner

At approximately 17:05, iPhone Filza App Manager search for `watch` showed:

- `Watch [com.apple.Bridge]`
- `com.apple.NanoTimeKit.CreateWatchFace` (listed; its container was **not yet demonstrated open**)
- A WatchFace renderer entry
- A separate Time Sync app

The user opened **Watch [com.apple.Bridge]** and observed exactly these entries at the top of its **application data container**:

```text
tmp/
SystemData/
Library/
Documents/
.com.apple.mobile_container_manager.metadata.plist
```

This is sufficient to establish the iPhone Watch application container is listable. It does **not** demonstrate reading paired-Watch `DeviceRegistry` files, modifying the Watch serial number, obtaining direct watchOS filesystem privileges, or installing a restricted Hermès FaceBundle.

**Caution:** `SystemData/` in this view is a *child directory of the app's data container*, **not** `/private/var/containers/Data/System`. The displayed `/dev/disk2s8 26.2 GB` is volume information, **not** the watch app's stored-data footprint.

These are source-file locations in the ZIP, not claims of successful privilege elevation:

| File | Code evidence | Practical interpretation |

| `WQFilzaIntegration.m` lines 100–124 | Candidate root paths include application, AppGroup, daemon, SystemGroup and system data | **Candidate strings ≠ granted access**; each must be tested independently |
| `WQFilzaIntegration.m` lines 195–227 | `worse_query` and fallback query/retry mechanism | Actual permission relies on returned sandbox extension and open/stat checks |

| `WQLSStore.m` | LaunchServices parsing/indexing | Consistent with App Manager discovery release notes |
| `Makefile` lines 15–19 | Compiles Tweak, MCM and worse_query integration; separate kexploit/XPF source is **not** in the compilation list | Do not describe source tree as an already operational iOS kernel jailbreak |
| `Tweak.m` lines 2623–2639 | WebDAV starts after 2.5s unless `WQWebDAVAutoStart` exists and is false; SSH optional | Review installed network-service settings immediately |
| `WQWebDAVServer.m` line 794 | If `gUsername` empty, HTTP auth returns `YES` | **Potential unauthenticated network WebDAV** |
| `WQWebDAVServer.m` lines 944–968 | Listener binds IPv4 `INADDR_ANY` / IPv6 `in6addr_any` | May accept connections from other reachable devices, not only local host |

**Recommended immediate mitigation:** turn off WebDAV **and** SSH in Filza settings, especially on shared Wi‑Fi. Do not expose or share the phone's network service address or passwords. Do not enter or publish serial number, UDID, Activation Lock, signing tokens or device pairing secrets.

## Minimal non-destructive follow-up

- Inspect only **folder names** under `Watch [com.apple.Bridge] → Library/` and optionally `Documents/`, without editing plist/SQLite files.
- If present, identify **folder names only** in the separately listed `com.apple.NanoTimeKit.CreateWatchFace` data container.
- Do not change serial numbers, device registry, watch face backup, SystemGroup/MG files or pairing state in the absence of an independently confirmed watch-side write and recovery method.
- Confirm the iPhone's *exact* iOS version only if needed to evaluate scope; Filza version does not establish iOS version.

**No executable source change to HermesEnabler, no new watch UI or folder clone.**
